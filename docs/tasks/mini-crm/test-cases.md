# Тестирование

## Условия запуска

API и E2E работают с настоящим Auth и PostgreSQL на отдельном тестовом стенде.
Нужны применённые миграции, демонстрационные пользователи и приватный `.env.local`.
Тесты создают собственные записи и очищают только принадлежащие им UUID.

## Автоматизация

| Слой   | Файлы                                                                                              | Состав                                               |
| ------ | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| Unit   | [domain](../../../src/domain.test.ts), [query-client](../../../src/query-client.test.ts)           | 5 строк матрицы + 3 регрессии кэша                   |
| API/DB | [security.test.mjs](../../../tests/security.test.mjs)                                              | 11 групп, включая запрещённые переходы и конкуренцию |
| UI/E2E | [workflow](../../../tests/e2e/workflow.spec.ts), [usability](../../../tests/e2e/usability.spec.ts) | 14 сценариев × desktop/mobile                        |

Адаптивность: [responsive](../../../tests/e2e/responsive.spec.ts). Проверки не
считают горизонтальный скролл таблицы достаточной адаптацией для телефона.

Инфраструктурные проверки: [блокировки и пароли](../../../tests/concurrency.py),
[правила Nginx](../../../tests/proxy.test.mjs). Запускаются на Linux Docker-хосте.

Chromium: 1280 × 800 и 390 × 844 с touch-emulation. Дополнительные сценарии
проверяют ширины 320, 360, 390, 430 и 768 px и форму на высоте 480 px. Один worker,
без автоматических повторов теста. Основной путь не подменяет ответы API;
управляемые ошибки и задержки используются только для проверки транспорта.

Команды из корня подготовленного тестового стенда:

```sh
pnpm typecheck
pnpm test
pnpm build
pnpm test:api
pnpm test:db
pnpm test:proxy
pnpm exec playwright install chromium
pnpm test:e2e
```

Отдельный сценарий:

```sh
pnpm test:e2e --project=desktop --grep 'FLOW:'
pnpm test:e2e --project=mobile --grep 'FORM:|LAYOUT:'
```

По умолчанию E2E обращаются к `http://127.0.0.1:8788`. Для другого стенда
установите `E2E_BASE_URL`; frontend должен использовать ту же базу, что и тесты.
HTML-отчёты и снимки падений игнорируются Git и требуют проверки перед публикацией.
Auth-сессии не сохраняются в отдельные файлы; сетевые traces и видео отключены.

## Границы проверки

- В браузерных сценариях один постановщик и два исполнителя; отдельный API-тест
  создаёт второго постановщика, проверяет общую задачу/историю и удаляет свои данные.
- Реальные iOS/Android, Firefox/WebKit, скринридеры и нагрузка не квалифицированы.
- Резервное восстановление и отказоустойчивость не проверялись.
- Проверка текущего дерева/bundle не заменяет аудит всей истории Git и зависимостей.
- GitHub Actions не настроены; проверки запускаются командами репозитория.
