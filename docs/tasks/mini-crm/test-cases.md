# Проверки и приёмка задачи мини-CRM

## Базовая версия и условия

Матрица относится к приложению `a147e84`, проверенному на Firebat1
5 ноября 2026 года. Исходное ТЗ и критерии находятся в
[requirements](requirements.md), фактический итог — в
[current-stage](current-stage.md). Подробная пользовательская последовательность
остаётся в [workflow](../../workflow.md), а не дублируется здесь.

Предусловия: отдельная тестовая база с применёнными миграциями, один постановщик
и два исполнителя, приватный `.env.local`, frontend и тесты подключены к одной
базе. Автотесты используют собственные UUID и очищают только принадлежащие им
записи. Seed, сброс и тестовые записи не применяются к рабочей клиентской базе.

Браузерный runner — Chromium, 1280 × 800 и 390 × 844 с touch-emulation.
Один worker, retries = 0. Сценарии работают с настоящим API и базой;
транспорт подменён только для воспроизводимой ошибки/задержки сети.
Набор не скрывает падение автоматическим перезапуском.

Для регрессий валидации, устаревшей истории, сообщения сети и комментария из
whitespace сначала зафиксированы падения, затем успехи тех же проверок.
Это подтверждает способность обнаружить найденные ошибки, а не только наличие
тестовых файлов.

## Как воспроизвести

На подготовленном выделенном тестовом стенде из корня репозитория:

```sh
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm build
pnpm test:api
pnpm exec playwright install chromium
pnpm test:e2e
```

API/E2E читают приватный `.env.local`. Стандартная цель E2E —
`http://127.0.0.1:8788`; другой тестовый адрес задаётся через `E2E_BASE_URL`.
Порядок создания новой установки и применения миграций — в
[README](../../../README.md). Начальную установку не выполнять поверх
проверенного существующего стенда.

Проверка отдельного сценария:

```sh
pnpm test:e2e --project=desktop --grep 'FLOW:'
pnpm test:e2e --project=mobile --grep 'FORM:|LAYOUT:'
```

Для проверки именно опубликованной версии дополнительно открыть публичный URL,
сверить отданные assets с целевым артефактом и пройти затронутое действие.
Успешная локальная сборка этого не доказывает.

HTML-отчёты и снимки падений находятся в игнорируемых `playwright-report/`
и `test-results/`. Это приватные артефакты; перед передачей проверять их на
учётные данные. Auth-сессии готовятся в памяти, сетевые traces и видео отключены.
В публичный комплект включается итог, а не пароли, токены или сырые auth-логи.

## Границы подтверждения

- Демонстрация и E2E используют одного постановщика и двух исполнителей.
  Несколько постановщиков допускаются схемой и проверкой роли без привязки к
  конкретному ID; отдельный сквозной прогон с двумя постановщиками не выполнялся.
- Реальные iOS/Android, Firefox/WebKit, скринридеры, полный аудит доступности,
  нагрузка, длительное наблюдение и масштабная база не квалифицированы.
- Восстановление из резервной копии, аварийный failover, постоянный домен и
  эксплуатационные гарантии не проверены и не входят в результат тестового ТЗ.
- Проверка известного набора действующих секретов в текущем tracked tree/bundle
  не равна полному аудиту зависимостей, всех возможных секретов и истории Git.
- Hosted CI не запускался: workflow GitHub Actions в проверенной версии отсутствует.
- Решение заказчика, отправка сообщения и 30–40-минутный созвон не состоялись
  либо не зафиксированы. Их нельзя отметить PASS по результатам автотестов.
