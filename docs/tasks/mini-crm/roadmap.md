# Этапы разработки и архитектура

## Этапы

| Этап           | Результат                                                           |
| -------------- | ------------------------------------------------------------------- |
| Анализ         | Требования, роли, инварианты и границы функциональности             |
| Проектирование | Модель данных, матрица статусов, RLS и атомарная история            |
| Реализация     | Auth, экраны, формы и типизированные запросы                        |
| Ревью          | Проверка владельцев правил, безопасности и обработки ошибок         |
| Тестирование   | Unit, прямой API, полный цикл пользователя и mobile                 |
| Публикация     | Собранный frontend, применённые миграции и проверка отданных файлов |

Требования связаны с проверками в [requirements](requirements.md).
Пользовательская последовательность описана в [workflow](../../workflow.md).

## Границы ответственности

```text
React: экраны → формы → API-клиент
                           ↓
Nginx: frontend + /api → Auth / PostgREST
                                    ↓
PostgreSQL: profiles / sites / tasks / task_history
            grants + RLS + транзакционные функции
```

- Auth устанавливает пользователя; защищённый профиль определяет роль.
- PostgreSQL владеет доступом, статусом и историей.
- API-клиент выполняет типизированные запросы и преобразует ошибки транспорта.
- React Query владеет серверным кэшем сессии; формы — несохранённым вводом.
- UI показывает допустимые действия; окончательное решение принимает база.

## Изменения и обновление

1. Связать изменение с требованием и воспроизводимым сценарием.
2. Исправить правило в его слое; обновить затронутые проверки.
3. Пройти типизацию и релевантные unit/API/E2E.
4. Собрать frontend; на существующей базе применить только новые миграции.
5. Сверить отданные файлы с целевой сборкой и проверить пользовательское действие.

Применённые миграции сохраняются. Статические файлы и база обновляются отдельно.
Для возврата frontend нужен ранее проверенный совместимый артефакт; обратное
изменение схемы оформляется новой миграцией с сохранением данных.
Команды новой установки находятся в [README](../../../README.md).
