## Реализация и ревью

Проверены границы: Auth устанавливает пользователя, защищённый профиль задаёт
роль, RLS/grants ограничивают данные, RPC владеет переходом и историей.
Кнопки — представление правил. React Query владеет серверным кэшем сессии,
формы — несохранённым вводом. Отдельный прикладной backend и параллельная
реализация авторизации не добавлялись.

| Найденное                                                                    | Исправление и подтверждение                                                                  |
| ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Устаревший переход мог попасть в повтор транзакции вместо быстрого конфликта | SQLSTATE `PT409`, проверка одновременного запроса и единственной записи истории              |
| Запись могла завершиться при старом выполняющемся чтении истории             | Отмена старого чтения и инвалидация после записи; unit-регрессия кэша                        |
| После конфликта обновлялся статус, но не история                             | Обновление обоих запросов и возврат на первую страницу; `STALE`                              |
| Названия/адрес из пробелов давали техническую ошибку                         | Полевая валидация, фокус и понятная ошибка; `FORM`                                           |
| При сетевом сбое сохранения показывался `TypeError`                          | Понятное сообщение, ввод сохранён, повтор доступен; `ERROR`                                  |
| Назад центрировалась, таблица на телефоне дробила слова                      | Компактная шапка, выравнивание слева, прокрутка таблицы; `LAYOUT`                            |
| После закрытия формы мог теряться фокус                                      | Сохранение открывшего элемента до autofocus; `FORM`                                          |
| У выбранных объекта и исполнителя не было постоянных подписей                | Видимые labels в новой и редактируемой задаче; `FORM` и ручной просмотр                      |
| Прямой API принимал комментарий только из табуляции/переносов                | Новая миграция нормализует whitespace; API-регрессия сначала обнаружила ошибку, затем прошла |

Это саморевью и технические проверки, а не независимое человеческое ревью
или приёмка заказчиком. Открытых блокирующих дефектов в проверенных сценариях
ТЗ не зафиксировано. Непроверенные области перечислены в test-cases.

## Доказательства итогового состояния

На Firebat1 для версии `a147e84` прошли TypeScript/сборка, 9 unit,
8 групп API и 20 E2E: 10 desktop и 10 mobile. Последний E2E-прогон после
миграции проверки комментария завершился без падений и автоматических повторов.

Отдельно проверены публичный HTTPS-интерфейс в Codex IAB, размеры и подписи
форм, возврат фокуса, мобильная таблица/навигация и отсутствие горизонтального
переполнения страницы. Отданные HTML/JS/CSS побайтно сверены со сборкой;
проверены отключённая регистрация и отсутствие действующих приватных значений
в отслеживаемом исходном дереве и bundle. Это не заявляется аудитом всей истории Git.

После очистки fixtures остались 3 профиля, 3 объекта, 5 задач в пяти статусах
и 14 записей истории. Приватный receipt проверки хранится вне Git;
машинные логи, пароли и полные auth-артефакты в этот комплект не включены.
Команды и соответствие сценариям — в [test-cases](test-cases.md).

GitHub Actions в проверенной версии не настроены; hosted CI не обозначается
как прошедший. Проверки выполнялись командами репозитория на выделенном стенде.

## Ограничения, которые остаются открытыми

- Публичный адрес Cloudflare временный и меняется при пересоздании туннеля.
- Прогоны Chromium/mobile emulation не равны проверке реальных iOS/Android
  и всех браузеров. Нагрузка и полный аудит доступности не выполнялись.
- Резервное копирование, мониторинг и готовность к реальным клиентским данным
  не входили в выполненный объём. Демонстрация не обозначается production CRM.
- Независимое ревью и приёмка заказчика ещё не состоялись.

Эти ограничения раскрываются при сдаче; они не подменяются обещаниями
непорученной доработки. Новый объём оформляется отдельно от завершённой
реализации тестового задания.
